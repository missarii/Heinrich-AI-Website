MCP Server

Overthink

Strict discipline layer for AI coding agents

Overthink is not another LLM — it is a control layer that forces the agent to triage first, investigate with evidence, take one useful action at a time, avoid loops, verify before claiming success, and finish on time. Purpose-built for Heinrich AI.

  • Fast triage — complexity level, time box, and budgets before any work starts
  • Action Guard — blocks wasteful patterns, side-paths, and risky commands
  • Evidence first — diagnosis and verification engines reject guesswork
  • Anti-loop — progress tracking detects stagnation and forces a stop
  • Mandatory verify — only real test/build results count as done

MCP Server · Toolkit

Mila

AI UI/UX intelligence for autonomous agents

Mila teaches coding agents how to build beautiful, production-ready interfaces with mathematical precision and zero “AI slop”. Component registry, design rules, code review, and seven MCP tools — ready for Heinrich, Cursor, Claude Code, and more.

  • Component registry — curated React/Tailwind components and templates
  • Design rules — typography, 8pt grid, color, motion, anti-patterns
  • 7 MCP tools — search, get component, themes, review, auto-fix
  • Theme generation — accessible palettes and Tailwind v4 @theme blocks
  • Code auditor — scores UI quality and suggests concrete fixes

Philosophy

An agent that stays honest

Heinrich AI is designed so you always understand what happened and why. Approvals are explicit. Actions are logged. Checkpoints are recoverable. The goal is not to replace the engineer — it is to amplify disciplined engineering.

Visible control

Sensitive actions require your confirmation. You remain the decision-maker.

Local-first context

Your workspace, secrets, and project state stay under your control.

Recoverable work

Git checkpoints and task history mean nothing is lost if a session is interrupted.
